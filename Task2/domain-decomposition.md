## Обоснование разделения системы на домены

В целевой архитектуре «Будущего 2.0» используется доменный подход, при котором каждое бизнес-направление самостоятельно управляет своими данными, бизнес-логикой и контрактами взаимодействия с другими системами.

Выделены следующие домены:

1. **Клинический домен** — отвечает за медицинские карты, записи пациентов, медицинские услуги и другие операционные процессы клиник. Медицинские данные остаются в защищённом контуре и не передаются в общую аналитическую платформу.
2. **ИИ-домен** — отвечает за обучение и эксплуатацию моделей искусственного интеллекта. Взаимодействует с клиническим доменом через контролируемые интерфейсы. В общую платформу передаются только разрешённые метрики моделей и агрегаты.
3. **Финтех-домен** — обеспечивает платежи, кредитные продукты и финансовые операции. Самостоятельно отвечает за выполнение требований безопасности, включая PCI DSS.
4. **Корпоративный домен** — управляет финансами, персоналом, закупками и корпоративными показателями. Формирует KPI для головного офиса.
5. **Партнёрский домен** — обеспечивает взаимодействие с фармацевтическими компаниями, управление контрактами, справочниками и обмен партнёрскими данными.
6. **Домен медицинского оборудования** — отвечает за телеметрию, калибровку, версии программного обеспечения и данные подключённых устройств.

### Принципы взаимодействия доменов

Для обмена данными используется общая интеграционная платформа, которая обеспечивает приём данных, проверку контрактов, классификацию и контроль качества.

При этом бизнес-логика остаётся внутри соответствующих доменов. Общая платформа не должна становиться новым централизованным хранилищем бизнес-правил.

Обмен осуществляется посредством API, событийной интеграции и CDC в зависимости от требований конкретного сценария.

Для аналитических задач используется единый конвейер обработки данных Raw → Curated → Gold. Подготовленные витрины доступны через семантический слой и портал самообслуживания.

### Преимущества выбранного подхода

**Независимое развитие бизнес-направлений.** Клинический, финтех- и ИИ-домены могут изменять свои внутренние системы без необходимости вносить изменения в центральное DWH.

**Ускорение подключения новых партнёров.** Новые фармацевтические компании и производители оборудования подключаются через согласованные API и контракты данных. Это сокращает объём индивидуальных интеграционных доработок.

**Снижение зависимости от легаси.** SQL Server 2008 постепенно перестаёт быть центром бизнес-логики и используется только как временный источник данных до завершения миграции.

**Повышение безопасности.** Медицинские и финансовые данные обрабатываются в соответствующих защищённых контурах. В общую аналитическую платформу поступают только разрешённые данные.

**Ускорение аналитики.** Единые витрины, семантический слой и портал самообслуживания позволяют бизнес-пользователям самостоятельно формировать отчёты и получать сопоставимые показатели.

Таким образом, выбранное разделение обеспечивает независимость бизнес-направлений, упрощает масштабирование компании и создаёт технологическую основу для подключения новых партнёров без необходимости изменения центрального DWH.
